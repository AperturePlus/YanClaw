# Yanclaw Crawler Agent — 需求文档

## 1. 项目概述

Yanclaw Crawler 是一个基于 LLM 的智能爬虫智能体，用于自动化采集中国高校研究生导师信息。
它不依赖静态 HTML 解析规则，而是利用大语言模型理解网页内容，自主探索导航结构，
从大学首页出发逐步发现学院列表和师资页面，最终提取结构化的导师信息并存入数据库。

系统分为两层：`runtime` 提供所有 agent 共享的运行时原语，`agents/crawler` 实现爬虫业务逻辑。

## 2. 核心需求

### 2.1 自主探索能力

- **输入**: 大学名称 + 官网 URL（来自 `assets/websites.md`）
- **无需预定义路径**: Agent 从大学首页出发，自主发现学院列表页、师资页面、教师详情页
- **探索策略**: 大学首页 → 院系/学院列表 → 某学院师资页面 → 教师个人主页
- **智能导航**: LLM 分析页面中的链接，判断哪些链接可能通向师资信息

### 2.2 信息提取

每位导师需提取以下字段（尽力而为，非必填字段允许为空）：

| 字段 | 必填 | 说明 |
|------|------|------|
| 姓名 | ✅ | 教师姓名 |
| 大学 | ✅ | 所属大学 |
| 学院 | ✅ | 所属学院 |
| 职称 | ❌ | 教授/副教授/讲师等 |
| 研究方向 | ❌ | 研究领域关键词 |
| 邮箱 | ❌ | 联系邮箱 |
| 电话 | ❌ | 联系电话 |
| 个人主页 | ❌ | 教师个人页面 URL |
| 履历 | ❌ | 教育/工作经历摘要 |
| 招生偏好 | ❌ | 招生要求、偏好方向 |
| 学术成果 | ❌ | 代表性论文/项目 |

### 2.3 LLM 驱动解析

- 不使用 BeautifulSoup/XPath 等静态解析
- 将网页文本内容发送给 LLM，由 LLM 返回结构化数据
- LLM 通过 tool calling 机制将数据存入数据库
- 支持配置不同的 LLM provider（OpenAI API 兼容接口）
- 不使用 langchain，自行封装 LLM 调用和 tool calling 循环

### 2.4 并行调度

- CrawlDispatcher（crawler 子系统内部调度器）可同时调度多个 CrawlerAgent
- 每个子任务负责一所大学的爬取
- 并发数可配置，避免资源耗尽
- 各子任务独立运行，互不影响

### 2.5 请求频率控制

- 对同一域名的请求间隔不低于可配置的最小值（默认 2 秒）
- 支持全局并发请求数上限
- 遇到 429/503 等状态码时自动退避重试
- 指数退避策略，最大重试次数可配置

### 2.6 数据持久化

- 使用 SQLite 作为本地存储
- 支持增量更新（同一教师不重复插入，而是更新）
- 记录爬取状态，支持断点续爬

### 2.7 避免重复抓取

- **运行内去重**: 维护已访问 URL 集合
- **跨运行去重**: 查询数据库 CrawlLog，跳过已成功抓取的 URL
- **大学级去重**: 跳过已完成的大学
- **数据去重**: 同名同学院教师 upsert 而非重复插入

### 2.8 路径震荡防护

Agent 自主探索时必须防止陷入循环或在无关页面间来回跳转：

- 已访问 URL 集合（双重去重：内存 + 数据库）
- 最大探索深度限制（默认 4 层）
- 有限回退机制（最大回退次数，默认 3 次，超过则放弃当前分支）
- 同域名约束（只跟踪同域名/子域名链接）
- LLM prompt 约束（告知已访问 URL，禁止推荐重复链接）

### 2.9 Skills 体系

- 每个 agent 有独立的 `skills/` 目录，以 markdown 文件形式存储 skills
- Skill 文件遵循统一规范（frontmatter + 结构化正文）
- 数据库存储所有历史版本（全量），支持回滚和 diff
- 当前 `.md` 文件 = 最新版本，修改前必须先存储老版本到数据库
- 共享元 skill `create-skills.md` 教 LLM 如何创建/修改 skills
- LLM 根据 skill 的 name + description 自行选择加载哪些 skills
- 执行完成后 LLM 反思执行经验，决定是否更新/创建 skills（自我进化）

### 2.10 上下文窗口管理

- Token 预算管理：按优先级分配（system prompt > tools > skills > 页面内容 > visited_urls）
- 长页面分块处理：超出预算时按段落边界切分，每块独立处理后合并结果
- 已访问 URL 列表截断：过多时只保留最近 N 条

## 3. 非功能需求

### 3.1 可观测性（日志）

- 控制台输出 INFO 级别摘要
- 文件输出 DEBUG 级别详细日志（`logs/crawl_{timestamp}.log`）
- 每个 Agent 使用带大学名前缀的 child logger
- 必须记录：页面抓取、LLM 调用、tool 执行、数据库写入、回退决策、跳过原因

### 3.2 容错性

- 单个页面失败不影响整体流程
- 网络错误自动重试后跳过
- LLM 错误自动重试后跳过
- 数据库错误事务回滚

### 3.3 可配置

LLM 端点、并发数、频率限制等通过环境变量 / `.env` 文件控制。

### 3.4 代码风格

- Python 3.11+
- 遵循 Python 哲学：async/await、类型注解、dataclass/Pydantic
- runtime 提供原语，不提供 workflow/状态机（避免上帝对象）
- 各 agent 用 runtime 原语自行编排业务流程

## 4. 约束

- Python 3.11+
- 仅用于学术信息公开页面的采集
- 不处理需要登录的页面
- 不存储个人隐私信息（仅公开的学术信息）
- 不使用 langchain，自行封装
